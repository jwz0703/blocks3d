# Blocks3D

A block-based editor for 3D projects, forked from [TurboWarp](https://turbowarp.org) (see `ROADMAP.md`). It has **no extension sandbox**.

- Every custom extension (URL, file or pasted text) runs **unsandboxed**; the option cannot be changed.
- Extensions saved inside a project load automatically, with no prompt.
- Custom blocks can return values (the "Custom Reporters" feature) by default; it is no longer an entry in the extension library.
- Infinite Clones, Remove Fencing, Remove Miscellaneous Limits and High Quality Pen are always on and no longer appear in Settings (project options and URL parameters cannot turn them off).
- Default framerate is 60 FPS. It can still be changed in Settings, by `?fps=`, or by stored project options.
- Other permission prompts (fetch, open window, camera, microphone, etc.) are unchanged.
- The Sounds tab is gone. The **Files** tab (檔案, right of Costumes) lists the current sprite's sounds first, then project-wide files stored inside the project file. Uploading or dropping an audio file (mp3, wav, ogg, flac, aac, m4a) adds it as a sound and opens the normal sound editor; its menu also has the sound library and recording. Anything that used to open the Sounds tab opens this tab. 3D sprites and the 程序物件 blocks can load `.glb`/`.gltf` models from it, and the built-in 檔案 category (always loaded, shown right after My Blocks) reads files as text, data URL or size.
- Projects are saved as **`.3dsb`** (File → Save, downloads, restore points, exports). `.sb3` / `.sb2` / `.sb` projects can still be opened, from the File menu or by dropping the file anywhere on the page; their sprites become 2D sprites. There is no way to save as `.sb3`.
- **3D is part of the runtime.** Sprites are either 2D or 3D. 3D sprites have x / y / z (y is up, z is depth), rotation x / y / z in degrees (yaw, then pitch, then roll), scale x / y / z, a model list (basic shapes or `.glb`/`.gltf` files from the Files tab) and a material (color, opacity, texture). The 3D scene is drawn above the backdrop and below pen and 2D sprites. The stage has an environment (background color or equirectangular skybox image, ambient light, sun, fog, camera) that is saved with the project.
- **Editing 3D sprites.** The add-sprite menu has **新增 3D 角色** (a basic shape, an uploaded `.glb`/`.gltf`, or a model already in the Files tab); sprite list and model thumbnails are rendered offscreen. For a 3D sprite, the sprite info panel shows position, rotation and scale x / y / z (with a lock for even scaling) and show / hide, and the Costumes tab becomes **模型**: the model list (switch, add, duplicate, reorder, delete, rename, change a model's shape or file) plus the sprite's color, opacity and texture (an image from the Files tab). The palette of a 3D sprite has **3D 動作** (move forward, turn / set yaw, pitch, roll, go to / change / set x y z, face a sprite, the camera or a point, and reporters with monitors), **3D 外觀** (switch / next model, color, opacity, scale, show, hide, model number / name) and 3D touching / distance at the top of Sensing, in place of the 2D ones. The opcodes are `motion3d_*`, `looks3d_*` and `sensing3d_*`.
- **One rule table for 2D and 3D blocks.** `scratch-vm/src/engine/block-support.js` says what every block does on 2D and on 3D sprites (keep, a 3D version, hidden, or nothing yet). The palette, the interpreter, the compiler and extensions all follow it, and blocks that do nothing on the current kind of sprite are drawn faded in the workspace. 2D blocks that point at a 3D sprite (go to, point towards, distance) use where it is drawn on the stage; 3D blocks that point at a 2D sprite get nothing (distance 10000); 2D and 3D sprites never touch. On 3D sprites, go to / glide to take a random point or the mouse on the ground, size is the even scale, and speech bubbles sit on top of the sprite. "[property] of [sprite]" offers z, yaw, pitch, roll, model, scale and opacity for 3D sprites, and **[3D 角色] 的螢幕 x / y** and **在畫面內？** let 2D sprites follow 3D ones. Directions are written down in ROADMAP.md (forward is -z, like the camera).
- **Canvas sprites** (**新增畫布角色**): a 2D sprite whose picture is a Canvas2D. The pen draws on one (**畫在 [畫布] 上** picks which), so pen trails can change layers, move, scale, hide, and "touching color" sees them; `.sb3` projects that use the pen get one behind every sprite, where the pen layer was. Extensions and libraries such as rough.js or paper.js can draw with `target.getCanvas()` / `getContext()`; the canvas is only uploaded in frames where something drew on it. A 3D sprite's texture can be a canvas sprite (`canvas:<name>`). Drawings aren't saved, like the pen layer.
- **Stage edit mode** (editor only, not fullscreen or the player). The stage shows a separate editor camera: drag empty space to orbit, right or shift drag to pan, scroll to zoom, F to frame the selected sprite. Clicking a 3D sprite selects it; dragging it moves it along the ground (shift: up and down). The selected sprite has a move / rotate / scale gizmo. With the pointer over the stage, G / R / S move, rotate or scale it with the mouse like Blender: X / Y / Z lock to an axis (again for its own axis), Shift + X / Y / Z lock to a plane, type a number for an exact amount, Ctrl snaps, left click or Enter confirms, right click or Esc cancels; Alt + G / R / S resets. A toolbar on the stage switches tools, toggles the grid, axes and game camera outline, aligns the editor camera with the game camera, and switches between the editor and game cameras. The green flag switches to the game camera and stop switches back. 2D sprites are on top, so they still get clicks and drags first.
- The 3D extension became **程序物件** in the extension library (not loaded by default; a project that uses its blocks loads it, and its category goes after 環境): objects created and changed by name, in the same scene as the 3D sprites (opcodes `three3d_`). The camera is a camera sprite and the environment belongs to the backdrop, so the camera, mouse look and environment blocks are in the 相機 and 環境 categories. 相機 also has follow blocks: 第三人稱跟隨 / 第一人稱跟隨 a 3D sprite, with offset, angles and smoothing, and 環繞 a 3D sprite or a point like three.js's OrbitControls (dragging the stage turns it, the wheel or pinching zooms, with damping, distance and pitch limits and turning by itself; drags that start on a 2D sprite or a 3D sprite with mouse scripts don't turn it) (`scratch-vm/src/engine/scene-3d-follow.js`), and `相機震動 強度 () 持續 () 秒`, which moves where the camera is drawn without turning it or moving the camera sprite; 3D 動作 has `往 [前/後/左/右/上/下] 平移` for walking level with the ground. 「[顯示 / 隱藏] 3D 畫面」 is in 環境.
- **The order of a frame** (ROADMAP.md 6.6). Control has `當每幀 [更新 / 更新後] (經過秒數)`: between the green flag and stopping, every frame runs input, the 更新 scripts, the other scripts, physics, the 更新後 scripts, camera following and drawing, in that order. A sprite whose per-frame script of an earlier frame still waits skips it (the hat shows a warning when it contains waiting blocks). `廣播並等待` chains finish in the frame they start in. At the end of My Blocks, `呼叫 [角色] 的 [函式]`, `對每個 [角色] 呼叫`, `對 id 為 () 的 [角色] 呼叫` and the reporter `從 [角色] 呼叫` run another sprite's custom block right away in the caller's thread, as that sprite (`self.` is the sprite called); they remember the custom block by its prototype's id, so renaming it keeps them working, and they warn when the custom block waits.
- **Collision and physics with Rapier** (**物理**, ROADMAP.md 6.1 and 6.7). Every 3D sprite has a box or sphere collider; touching and raycasts use them, and dynamic / static / kinematic bodies, mass, bounce, friction, rotation lock, forces, impulses, velocity, gravity and `當碰撞到 / 當離開 [角色]` do physics between the green flag and stopping. Raycasts (`從 [我自己 / 目前的相機 / 滑鼠 / 角色] 往前的射線`, `從位置 () 往 () 的射線`) report `{hit, sprite, distance, x, y, z}`. Rapier is only loaded for projects that need it.
- **Clicks, attaching, animations and 3D sound** (ROADMAP.md 6.2–6.4 and 6.8). Clicking a 3D sprite runs `當角色被點擊` (2D sprites on top still come first), and Events has `當滑鼠移到這個角色上 / 離開這個角色` for every sprite. 3D Motion has `附著到 [角色]`, `取消附著`, `附著的角色`, `世界 [x…roll]` and `移到世界 x y z`: an attached sprite's position, rotation and scale are relative to its parent. 3D Looks plays the animations of GLTF models (`播放動畫`, `直到結束`, `停止動畫`, speed, `播放中的動畫`). Sounds of 3D sprites come from where they are, heard from the camera (`3D 音效 [開啟 / 關閉]`, `聲音在 () 內最大聲` in Sound).
- **Variables are paths.** There is no "Make a Variable" / "Make a List" button (and so no cloud variables). Variables are read and written with a path: the variable's name, then `.name` for a field, `[n]` for an item (the first is 1) and `["a.b"]` for names with dots or brackets, e.g. `enemies[1].x`. Values can be objects and arrays; lists are arrays. Which variables a block uses comes from its category:
  - **資料** (orange, in place of Variables): global variables, stored on the stage: `取得 ()`, `設定 () 為 ()`, `() 改變 ()`, `() 存在？`, `刪除 ()`, `從 () 取得 ()` (a path inside any value, e.g. `從 (Box 的位置) 取得 (x)`), `全域變數` (all of them as an object), array and object blocks (add, insert, delete / replace item, clear, item, position, length, contains, keys; the reading ones also take an array or object instead of a name) and JSON (`解析 JSON`, which gives an empty text for invalid JSON, `是有效的 JSON？`, `轉成 JSON` with a 格式化 option). A path can start with `self.` or `local.` to use the variables below, e.g. to add an item to a local array.
  - **分身變數** (end of Control, sprites only): `設定分身變數 () 為 ()`, `分身變數 () 改變 ()`, `取得分身變數 ()`, `分身變數 () 存在？`, `刪除分身變數 ()` and `分身變數`. They are stored on the sprite, and each clone gets its own copy. `x`, `y`, `z`, `id`, `name`, `visible`, `direction`, `size`, `costume`, `yaw`, `pitch`, `roll`, `position`, `rotation`, `scale`, `model`, `fov` and `backdrop` are the sprite itself (setting `x` moves it); sprites can't have variables with those names.
  - **區域變數** (pink, end of My Blocks): the same set for the custom block call they run in: every call (recursion, or several scripts running the same block at once) gets its own set, which is gone when the call ends. Outside a custom block, each run of a script gets its own set.

  Writing makes the objects and arrays on the way; reading a missing path gives an empty text. Storing a value copies it (`設定 b 為 (取得 a)`), while a path into a value changes it in place (`設定 a.x 為 1`). Objects and arrays show as JSON in text (join, say, monitors). 3D Motion has `移到位置 ()`, `滑行 () 秒到位置 ()` and `面向位置 ()`, and 3D Sensing `[角色] 的 [位置 / 旋轉 / 縮放]`, all as `{x, y, z}`. Vector math is the **向量** extension in the extension library (not built in).
- **The text block** (top of 資料) is text with line breaks (Enter starts a new line; Ctrl/⌘ + Enter or clicking elsewhere finishes) and `${path}`s that are filled in: `分數: ${分數}` for global variables, `${self.hp}` and `${local.i}` for the others. Only this block reads `${…}`; other text fields don't.
- **Clone ids.** `建立 [角色] 的分身 id = ()` gives the clone an id (分身變數 `id`); left empty, clones are numbered 1, 2, 3… (again from 1 once every clone is gone), and ids may repeat. `當分身產生 (id)` has an `id` to drag out like a custom block parameter. After the 分身變數 blocks, Control has `是分身？` (true in clones; the sprite itself is `not` it, so there is no "is original" block), `刪除 [角色] id 為 () 的分身`, `[角色] id 為 () 的分身存在？`, `[角色] id 為 () 的分身的 ()` and `設定 [角色] id 為 () 的分身的 () 為 ()`.
- Opening projects from before paths (`.sb3`, and `.3dsb` before format version 3) converts their variable and list blocks: stage variables become 資料 blocks, "for this sprite only" variables 分身變數 blocks, lists of sprites 資料 blocks with `self.` paths, and the old 變數 blocks 資料 blocks. A list with the same name as a variable of the same sprite is renamed (`名稱 清單`), and so is a sprite variable named like a built-in (`x 變數`). Old list reporters keep joining their items like Scratch.
- Control has a `讓 (i) 從 (1) 跑到 (10)` loop (counts down when the start is larger). Drag `i` out of it like a custom block parameter; it reads the closest enclosing loop with the same name, and is 0 outside one. A loop dropped inside another is renamed to a free name (`j`, `k`, …) automatically, and right-click → 重新命名變數 renames a loop and the parameters that belong to it.
- Control has a `摺疊區塊` C block (after the stop block) that only groups blocks to make scripts easier to read; the blocks inside always run once. Click its triangle to hide the blocks inside, which turns it into a comment-coloured single block, and click again to show them. Right-click → 重新命名 changes its name. Both are saved with the project.
- Sensing has `[ ] 鍵剛按下？`, `[ ] 鍵剛放開？` and `[ ] 鍵按住秒數` after `按下 [ ] 鍵？`. Key events are recorded as they arrive and become visible at the start of the next frame, so a tap shorter than one frame is still caught, and key repeat while holding does not count as a new press. Each 剛按下 / 剛放開 block reports a given press or release once per script (and once per clone), even in a loop that runs many times per frame or without screen refresh; the event is only available in the frame right after it happens. 按住秒數 is 0 when the key is not held; with 任意鍵 it is the longest held key.
- Looks ends with a `log ()` block that prints its input to the browser console (`console.log`).
- **File → 匯出為 HTML / 匯出為 ZIP** exports the project with this fork's own player, so 3D, files and every other change here keep working offline. The player is only the stage, filling the window, and the project starts right away (sound starts after the first click or key press). The ZIP holds `index.html`, `player.js`, `project.js` and a copy of `project.3dsb`, plus `music.js` / `three.js` / `rapier.js` when the project uses the music extension / anything 3D / collision or physics. To keep exports small, the player can't load Scratch 1/2 projects (it doesn't need to), only has the Scratch fonts that the project's vector costumes use, and the hardware extensions (micro:bit, LEGO, Force & Acceleration) in it do nothing.

> ⚠️ Unsandboxed extensions have full access to the page. Only load extensions and projects you trust.

- `scratch-render/src/RenderWebGL.js`: `setUnderlay(fn)`: `draw()` calls `fn(gl)` right after clearing the stage and before any drawable, then restores its own GL state
- `scratch-vm/src/engine/scene-3d.js` (`runtime.scene3D`): the 3D scene (three.js renderer, camera, lights, environment, model/geometry/material/texture caches, 3D sprites and procedural objects). three.js shares the stage's WebGL2 context and draws right before the pen layer through `setUnderlay(fn, 'pen')` (`scratch-render/src/RenderWebGL.js`), so no frame is copied between contexts. The scene renders into a 4× multisampled target (the stage context has antialiasing off) that is only re-rendered when something 3D changed (`markDirty()`, called by every 3D setter, so edits show up right away even while the project is stopped) or the stage size changed. Without WebGL2 (or with an unmodified scratch-render) it falls back to an offscreen canvas shown as a bitmap skin in the video layer. three.js is only required once something 3D exists, so the exported player can leave it out. `.gltf` buffers and textures are looked up in the Files tab
- `scratch-vm/src/sprites/target-3d.js` (`Target3D`): 3D sprites and clones. It extends `RenderedTarget` so scripts, variables, sounds, clones and the sprite list work unchanged, with its 2D drawable always hidden; it holds a `THREE.Group` in the scene. `sprite.js` has `kind` and the shared `models`, and creates `Target3D` for 3D sprites. Clones share geometry, and materials while their settings are the same. 3D sprites carry an in-memory placeholder costume (`tw-3d-placeholder.js`) for code that expects costumes; it is not saved in projects
- `scratch-vm/src/serialization/3dsb.js`: the `.3dsb` format (`meta.format`/`formatVersion` with the `MIGRATIONS` table, `kind` on targets, 3D sprite fields, stage `environment`). Blocks, variables, assets etc. still go through `sb3.js`, which only got a hook for `kind: "3d"`. `virtual-machine.js`: `loadProject` tries `.3dsb` first (skipping scratch-parser) and falls back to the Scratch loaders; `toJSON`/`saveProject3dsb`/`saveProject3dsbStream` write `.3dsb` (`saveProjectSb3*` are aliases); `addSprite3D`
- `scratch-vm/src/extensions/tw_three3d/index.js`: the 程序物件 blocks, now working on `runtime.scene3D`; an extension library item (`scratch-gui/src/lib/libraries/extensions/index.jsx`), placed after 環境 by `make-toolbox-xml.js`
- `scratch-gui`: `.3dsb` in `lib/sb-file-uploader-hoc.jsx` (open dialog, and dropping a project file anywhere), `containers/sb3-downloader.jsx`, `containers/tw-restore-point-manager.jsx` and `lib/tw-standalone-export.js` (which also exports three.js for projects with 3D sprites)
- `scratch-vm/src/extensions/tw_files/index.js`: new 檔案 extension; loaded at startup via `CORE_EXTENSIONS` in `virtual-machine.js`, removed from the extension library, and placed after My Blocks by `make-toolbox-xml.js`
- `scratch-vm/src/util/data-path.js`: paths (parsing, scopes, built-in properties of `self`, copying, arrays, JSON, `${}` text, vectors). Variables are ordinary `Variable`s found by name (so monitors, saving and clones work as before); `Target.duplicateVariable` deep-copies values for clones; `Cast.toString` shows objects as JSON. `scratch-vm/src/extensions/tw_data/` (`twdata`, the 資料 category in place of Variables), `tw_clone_vars/` (`twclonevars`: 分身變數 and clones by id, moved to the end of Control by `make-toolbox-xml.js`) and `tw_local_vars/` (`twlocalvars`), loaded via `CORE_EXTENSIONS`; `tw_data/path-blocks.js` lists every path block with its scope for the extensions and the compiler. `tw_vector/` (`twvector`) is the 向量 extension of the library. Modules in `src/lib/tw-standalone/` replace the parts most projects don't need; the music samples and three.js are built separately (`standalone-music.js`, `standalone-three.js`) and only exported with projects that use them
- 3D blocks in the compiler: `descend3DInput` / `descend3DStackedBlock` in `scratch-vm/src/compiler/irgen.js` and the `MOTION3D_*` opcodes in `jsgen.js` call `Target3D` directly. 3D objects are updated once per frame (`Scene3D.markTransformDirty` / `flushTransforms`)
- Frame phases: `Runtime._runFramePhase`, `hasResumableWaitingThread` and `isGameRunning` in `scratch-vm/src/engine/runtime.js` (the sequencer skips phase threads), the `control_whenframe` hat in `scratch3_control.js` and `scratch-gui/src/lib/blocks.js`
- Calls to other sprites: `scratch-vm/src/engine/cross-call.js`, `compileProcedures` in `compiler/compile.js`, `callSprites` in `jsexecute.js`, the interpreter in `scratch3_procedures.js`; the blocks (`procedures_callsprite*`) in `scratch-gui/src/lib/blocks.js`, added to My Blocks by `containers/blocks.jsx`; workspace warnings in `scratch-gui/src/lib/tw-block-hints.js`
- Physics: `scratch-vm/src/engine/scene-3d-physics.js` (`runtime.scene3D.physics`) and the 物理 blocks in `extensions/tw_3d/physics.js`. `@dimforge/rapier3d-compat` is loaded with `import()`, a chunk of its own in the editor; the exported player gets it from `standalone-rapier.js` (`src/lib/tw-standalone/rapier.js`)
- Picking (`Scene3D.pickTarget`, used by `io/mouse.js` and the hover hats in `extensions/tw_3d/events.js`), attaching (`Target3D.setParent3D` and the world pose methods), GLTF animations (`Scene3D.playAnimation`), 3D sound (`engine/spatial-audio-effect.js`, `Scene3D._updateAudio`, `extensions/tw_3d/sound.js`)
- Branding: `scratch-gui/src/lib/brand.js` (`APP_NAME` = Blocks3D, used by the page titles in `webpack.config.js` and most UI text), logo `components/menu-bar/blocks3d-logo.svg` (shown at the left of the menu bar; also `static/favicon.svg`), `static/favicon.ico` and `static/images/*.png`, `static/manifest.webmanifest`. The homepage footer only keeps the disclaimers and Credits, and the menu bar feedback button is gone. `scratch-vm/src/engine/tw-platform.js` says Blocks3D; projects whose platform is TurboWarp still load without the unknown platform warning (`sb3.js`)
- SVG bindings (ROADMAP.md 階段 10): `scratch-vm/src/engine/svg-bindings.js` (`runtime.svgBindings`, updated right before `renderer.draw()` in `Runtime._step`) redraws costumes whose SVG has `{expressions}` in text or attributes, or `data-bind-*` on groups, when the values change; clones and instances whose values differ get their own skin. The SVG is kept on the costume as `svgBindingSource` (`import/load-costume.js`, `VirtualMachine._updateSvg`). Expressions: `scratch-vm/src/util/b3-expression.js`, the same tokenizer and parser as `.b3s` (`tools/3dsb-text/simple.js`). `util/svg-binding-scan.js` finds bindings in SVG text with their lines (for tools and the code mode). `scratch-render` got `getDrawableSkinId`.
- Paint editor bindings: `scratch-paint/src/helper/bindings.js` keeps `data-bind-*` of groups in `item.data.bind` (paper.js `onImport` / `onExport` in `containers/paper-canvas.jsx` and `hocs/update-image-hoc.jsx`), doesn't reduce bound groups on import or ungroup, and draws the fixed canvas of costumes with bindings as a dashed guide; the 綁定 panel (`components/binding-panel/`) is in the top row of `components/fixed-tools/`. Elements bound in the code mode (any attribute) are replaced before import by `<g data-code-binding="markup">` around a copy worked out with empty variables (`prepareCodeBindings`), locked, and put back as they were when saving (`restoreCodeBindings`, placed by three anchor points that follow the editor's transforms).
- SVG code mode: `scratch-gui/src/components/tw-svg-code-editor/` (the 繪圖 / SVG 程式碼 switch in `containers/costume-tab.jsx`): the costume's SVG as text with line numbers, errors on their lines, a preview through the runtime's `Template` with test values (actual values while `runtime.isGameRunning()`), saved with `vm.updateSvg` when it is valid XML. Costumes load through `renderableSvg` (bindings worked out with empty variables), since the SVG renderer can't read `rotate({…})`.

- Sprite interfaces (ROADMAP.md 階段 10): `scratch-vm/src/engine/sprite-interface.js` (`runtime.spriteInterfaces`; `sprite.interface` = events and public custom blocks, saved as `interface` on sprites by `serialization/3dsb.js`, copied by `Sprite.duplicate`, sprite renames update the hats) and the built-in `twiface` extension (`extensions/tw_interface`: 廣播事件 / 廣播事件 值 / 廣播事件並等待 at the end of 事件, 「當收到 [角色] 的 [事件]」, 觸發的角色, 觸發的分身 id, 事件值; events are made, renamed and deleted from the menu of 廣播事件, like messages, handled by `handleMenuAction` in `containers/blocks.jsx`). Extension menu functions now also get the scratch-blocks block they are on (`extension-manager.js`), so the event menu follows the sprite menu. The GUI builds the categories (`interfaceCategories` in `scratch-gui/src/lib/make-toolbox-xml.js`: one category per other sprite with its hats and cross-sprite calls of its public custom blocks); right-clicking a custom block's definition makes it public (the `PROCEDURE_DEF_CONTEXTMENU` mixin is wrapped).
- Components (ROADMAP.md 階段 10): `scratch-vm/src/engine/components.js` (`runtime.components`): a definition is a `Sprite` with `sprite.component` ({id, color, props}) and its instances are targets of it that are saved (`isOriginal`) and have names of their own (`target.instanceName`, which `RenderedTarget.getName()` and `Runtime.getSpriteTargetByName` prefer), with their own property values (`target.componentProps`). Clones of an instance keep its name and values. Events of instances are sent as the instance and as `_any_<component>`. `serialization/3dsb.js` (format 4) moves definitions into `components` (the first instance's sprite data is the root) and keeps only an instance's own values; loading expands every instance and merges them onto one sprite; a definition without instances keeps a hidden target (`sprite.componentTemplate`). The built-in `twcomp` extension (`extensions/tw_components`) has the property blocks; the GUI puts them in the 元件 category of an instance (「建立一個屬性」 opens `components/tw-property-prompt`, and the menu of 屬性 has 新屬性… / rename / delete, like variables) and in the category of each component (`make-toolbox-xml.js`), with the sprite list's context menu (進入元件 / 包成元件 / 再放一個 / 重新命名元件 / 解除元件 / 刪除元件…), the values of the properties as one more row of the sprite info (`components/tw-component-props`, `extraRow` of `sprite-info.jsx`), grey blocks with a red outline for instances that aren't there (`isMissingReference` in `containers/blocks.jsx`), and sprite thumbnails drawn with the values of SVG bindings (`lib/tw-bound-costume-url.js`).
- Members and the component mode: a component's `members` (sprites of it, or instances of other components, with positions from the root) get targets in every instance (`componentOwner`, `buildMembers`), which move with it (`RenderedTarget.setXY` → `moveMembers`), aren't saved on their own (`sb3.serialize` skips them; `3dsb.js` saves `members` with the sprites' roots) and aren't found from outside (`getSpriteTargetByName`); `Components.resolveName` looks in the instance first, and events, broadcasts (`broadcastScope` in `Runtime.startHats`, plus 廣播到全域) and `cross-call.js` follow it. `VirtualMachine.enterComponent` / `exitComponent` / `setComponentView` set `components.editScope`: picking on the stage stays in it (`getTargetIdForDrawableId`, `componentLevelOf`), what is outside is hidden or faded (`refreshComponentEditView`), sprites added meanwhile go into it, edits of members go to every instance (`memberChanged`), and the green flag leaves it. GUI: `components/tw-component-mode/` (返回 as the first tile of the sprite list, `leadingItem`; the component in place of the stage, with how many instances, 顯示周圍 and 放入元件; the hint over an instance's blocks), `listIds` of the sprite list, shift-click (`lib/tw-sprite-multiselect.js`) and `makeComponentFrom`, and double-click on the stage (`enterComponentAtDrawable`).
